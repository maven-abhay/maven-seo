CMS & Web Platforms

Umbraco CMS Implementation & Upgrade

We implemented Umbraco CMS for our client’s website and upgraded it to a current, supported Umbraco release, giving the content team an easier editor and the business a secure, modern .NET platform. We also built the site to WCAG accessibility guidelines, so people using a keyboard, screen reader or zoom can use every page.

Plan your Umbraco upgrade
Platform
Umbraco CMS on .NET
Scope
New implementation and version upgrade
Focus
Editor experience, WCAG accessibility, security and SEO-safe migration

The challenge: Umbraco CMS upgrade

Older Umbraco versions stop getting security fixes once they leave support, and moving to a current version is more than a package update: newer Umbraco runs on modern .NET and has a rebuilt back office. The client needed to make that move without losing content, URLs or search visibility, and wanted the new site to meet WCAG accessibility guidelines.

What we did: Umbraco CMS upgrade

  • Umbraco installation and configuration
  • Document types and a clear content model
  • Reusable content blocks for editors
  • Content and media migrated to the new version
  • Custom code and packages updated or replaced
  • 301 redirects for any changed URLs
  • WCAG accessibility built into templates and blocks

The outcome: Umbraco CMS upgrade

The website runs on a supported Umbraco release with its content and media carried over, and editors build and update pages from ready-made blocks without waiting for a developer. Every page works with a keyboard and screen reader, and the guardrails in the editor keep new content accessible.

Our approach

From Legacy to Latest: The Umbraco Upgrade Path

The four steps we follow to move an Umbraco website to a supported version, without losing content or search visibility.

  1. 01

    Audit

    Review the current Umbraco version, packages, custom code, content and hosting to map what has to change.

  2. 02

    Plan

    Pick the target Umbraco version, list the breaking changes and agree the migration and rollback plan.

  3. 03

    Upgrade & migrate

    Move the code to modern .NET, replace unsupported packages, then migrate content and media.

  4. 04

    Test & go live

    Test pages, forms and editor workflows, set up redirects, then switch over and monitor.

WCAG accessibility

Accessibility Built In, Not Bolted On

We implemented WCAG accessibility across the Umbraco templates and content blocks, then checked it with automated tools and manual keyboard and screen reader testing.

01
Structure

Semantic Page Structure

Templates use proper headings, landmarks and lists, so screen readers can announce the page and users can jump straight to the content they need.

02
Keyboard

Keyboard Access & Visible Focus

Menus, accordions, sliders and forms all work without a mouse, with a skip link, a logical tab order and a clear focus outline.

03
Contrast

Colour Contrast & Readable Text

Text and buttons meet WCAG contrast ratios, and layouts reflow cleanly when users zoom or enlarge text.

04
Media

Alt Text & Accessible Media

Meaningful images carry alt text and decorative ones are hidden from screen readers, with captions where media needs them.

05
Forms

Accessible Forms

Every field has a visible label, required fields are marked, and error messages are announced and explain how to fix the problem.

06
Governance

Editor Guardrails in Umbraco

Document types and blocks guide editors toward accessible content, such as alt text fields on images and a fixed heading order, so the site stays accessible after launch.

Braze Patient Engagement Platform

We built and run the full Braze set-up for a healthcare provider: API integration, scheduled, action-based and API-triggered Canvases, patient data import and export, reusable templates and Content Blocks, subscription groups and message delivery audit logs.

Plan your Braze build
Industry
Healthcare
Platform
Braze
Scope
API integration, Canvas orchestration, patient data, content, consent and audit logs

The challenge: Braze patient engagement

Patient data sat in clinic, booking and CRM systems that Braze could not see. Reminders relied on manual lists, consent was a single on/off switch, and there was no quick way to check whether a patient’s message had actually been sent.

What we did: Braze patient engagement

  • Integration with the Braze REST API
  • Schedule, action and API-triggered Canvases
  • Patient custom attribute import and export
  • Email templates and Content Blocks
  • Subscription group management
  • Message sent log checks

The outcome: Braze patient engagement

Braze is now the one place where patient engagement is decided and delivered. Journeys run on their own, every message respects the patient’s choices, and any send can be traced back to the trigger behind it.

How it works

One Path from Patient Data to a Consented Message

Every message passes through one API layer and a consent check before it reaches the patient.

  1. Source systems

    Clinic, booking and CRM data and events.

  2. API layer

    Batched, retried and rate-limit aware calls into Braze.

  3. Braze Canvases

    Scheduled, action-based and API-triggered journeys.

  4. Consented delivery

    Subscription groups checked, then every send logged.

What we delivered

Ten Parts of a Healthcare Braze Build

Each part of the healthcare marketing automation platform, and the hard problems we solved in it.

01
Integration

Braze REST API Integration Layer

One shared service connects clinic, booking and CRM systems to the Braze REST API: user tracking and identity, messaging, Canvas triggers, exports, subscriptions and Content Blocks.

  • Rate-limit aware batching with retries and backoff
  • Idempotent writes, so a retry never duplicates an event
02
Recall

Schedule-Based Canvas Journeys

Recurring Canvases for check-up and screening recalls, prescription refills and renewals, timed against each patient’s own dates and sent in their local time zone.

  • Re-entry windows so no one gets the same reminder twice
  • Patients exit the moment they book, even mid-journey
03
Real time

Action-Based Canvas Journeys

Journeys that start the moment a patient acts, such as booking, abandoning a booking or placing an order, with event properties driving branches and personalisation.

  • Exception events handle late or out-of-order data
  • Priority rules and frequency caps across journeys
04
Transactional

API-Triggered Patient Journeys

Back-office systems start Canvases through the Braze API, passing live details such as appointment time and clinic into each message as Canvas entry properties.

  • Payloads validated, with no clinical detail in messages
  • Reschedules and cancellations re-route patients automatically
05
Data out

Patient Export by Every Method

Patient data exported by ID, by segment, for the global control group and from campaign and Canvas analytics, in the form each reporting, CRM and support team needs.

  • Background export jobs tracked, validated and loaded
  • Encrypted storage and only the fields each team needs
06
Data in

Patient Custom Attribute Import

A documented custom attribute model for last visit and next check-up dates, preferred clinic, care programme and language, loaded in bulk once and then kept fresh with incremental syncs.

  • Only changed values sent, to control data-point usage
  • Typed, normalised values so segments and Liquid never break
07
Content

Email Template Library

Responsive, on-brand email templates with Liquid personalisation, safe default values and conditional sections for clinics, products and languages.

  • Tested across major email clients and devices
  • Sends stop cleanly when required data is missing
08
Reuse

Content Blocks

Headers, footers, clinic details and legal text built once as Braze Content Blocks and reused in every email and Canvas step.

  • One edit updates every live message
  • Legal and privacy wording kept current in locked blocks
09
Consent

Subscription Group Management

Separate subscription groups for service messages, reminders, offers and newsletters, managed from a patient preference centre and kept in sync with the CRM.

  • When systems disagree, the opt-out wins
  • Every consent change recorded with its source and time
10
Assurance

Message Delivery Audit Logs

Message sent logs checked against each trigger and Canvas entry, so the team can show what was sent, to whom and why, and spot delivery failures early.

  • “Did my reminder send?” answered from evidence
  • Logs keep IDs and outcomes, not personal message content

Umbraco CMS & accessibility

Can you upgrade an old Umbraco website to the latest version?

Yes. We audit your current Umbraco version, packages and custom code, then upgrade the site to a current, supported Umbraco release on modern .NET and migrate your content and media.

Do you build new websites on Umbraco CMS?

Yes. We implement Umbraco from scratch, including the content model, page templates and reusable blocks, so your team can create and update pages without a developer.

Will we lose content or search rankings during an Umbraco upgrade?

We plan every upgrade to carry over your content, media and URLs, and we add 301 redirects wherever a URL has to change, so search engines and visitors still find every page.

Can you make our Umbraco website accessible and WCAG compliant?

Yes. We build Umbraco templates and content blocks to WCAG guidelines, covering page structure, keyboard access, colour contrast, alt text and accessible forms, add editor guardrails so new content stays accessible, and test with automated tools and by hand.

Braze, Salesforce & marketing

Can you integrate Braze with Salesforce?

Yes. We connect Salesforce to Braze so customer profiles, events and consent stay in sync, then use that data to power segments and automated customer journeys in Braze.

Do you also run marketing campaigns, not just the technology?

Yes. As well as building on Braze and Salesforce, we deliver marketing projects: campaign strategy and planning, email and lifecycle campaigns, segmentation and personalisation, A/B testing, landing pages and campaign reporting.

What marketing can a healthcare business automate?

Common examples are health check-up and screening recalls, appointment confirmations, prescription refill reminders, welcome series for new patients and personalised health content, each triggered by patient data.

How do you handle customer consent and privacy in marketing automation?

We sync each customer’s consent and channel preferences into Braze, message only people who have opted in, and keep sensitive health details out of marketing messages.

What types of Braze Canvas do you build?

We build schedule-based Canvases for recurring reminders, action-based Canvases that react to what a customer does, and API-triggered Canvases that your own systems start, each with entry rules, exit criteria and frequency caps.

Can you check whether a Braze message was sent to a specific person?

Yes. We check the Braze message sent logs and the person’s messaging history, and match them to the trigger and consent behind each send, so you can see what was sent, when and why.
