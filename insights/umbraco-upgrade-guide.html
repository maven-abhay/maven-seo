Umbraco Upgrade Guide: How to Move From Umbraco 7 or 8 to a Supported Version

Why legacy Umbraco sites need to move, what actually changes, and a step-by-step path that protects your content and search rankings.

6 min read By Manoj K Joshi, CTO & Co-Founder

Many organisations still run websites on Umbraco 7 or Umbraco 8. They work, so upgrading feels optional, until a security issue, a hosting change or a missing feature makes it urgent. This guide explains what changes, how to plan the move, and how to make sure your content and search rankings survive it.

Why upgrade from Umbraco 7 or 8

Both Umbraco 7 and Umbraco 8 have reached end of life, which means no more security fixes or updates. They also run on the older .NET Framework, which ties the site to Windows hosting and an ageing set of tools. Over time it becomes harder to host, harder to secure and harder to find developers who want to work on it.

Modern Umbraco runs on current, cross-platform .NET. It is faster to develop on, easier to host in the cloud, receives regular security updates and has a new, extensible backoffice for editors.

Key takeaways

  • Umbraco 7 and 8 have reached end of life and run on the older .NET Framework.
  • Moving to modern Umbraco is closer to a re-platform than a click-to-upgrade, so plan it as a project.
  • Audit packages and custom code first; they decide most of the effort.
  • Inventory every URL and set up 301 redirects so search rankings are protected.

What changes in modern Umbraco

  • The platform: since Umbraco 9, Umbraco runs on modern .NET instead of .NET Framework, so custom code, controllers and configuration must be updated.
  • The backoffice: the editor interface was rebuilt from Umbraco 14 onwards. Custom backoffice extensions written for the old AngularJS backoffice need to be rewritten.
  • Packages: some packages you rely on may have new versions, different replacements or no longer exist.
  • Templates and data: views, property editors and stored content may need changes or migration to match the new versions.

Upgrade or rebuild?

Within modern versions, upgrades are incremental: you move from one supported version to the next with relatively small changes. Moving from Umbraco 7 or 8 is different. Because the underlying platform changes, it is closer to a re-platform: content is migrated and code is moved or rebuilt on modern .NET.

That is also an opportunity. Many teams use the upgrade to clean up unused document types, simplify templates, improve page speed and refresh the design, so the effort delivers more than a version number.

The four-step Umbraco upgrade path

1. Audit

Record the current Umbraco version, hosting, packages, custom code, integrations, document types, content volume and every public URL. This tells you where the real effort lies.

2. Plan

Choose the target version, decide how each package and custom feature will be replaced or rebuilt, and agree a migration, testing and rollback plan with clear dates.

3. Upgrade and migrate

Move the code to modern .NET, rebuild templates and editor experiences, then migrate content and media. Tools such as uSync can help move settings and content between environments.

4. Test and go live

Test pages, forms, search, integrations and editor workflows. Check performance and accessibility, set up redirects, then switch over and monitor closely for the first weeks.

Protecting SEO during the upgrade

A CMS upgrade should never cost you search traffic. The key is to treat URLs and page metadata as part of the content you are migrating:

  • Inventory every URL from the current site, your sitemap and analytics before you start.
  • Keep URLs where you can, and add a 301 redirect for every URL that changes.
  • Carry over titles, meta descriptions, headings and structured data for each page.
  • Update the XML sitemap and submit it in Google Search Console after launch.
  • Watch Search Console for crawl errors and ranking changes in the weeks after go-live.

Choosing your target version

Umbraco publishes long-term support (LTS) and short-term support (STS) versions. For most business websites, an LTS version is the right target: it receives updates for longer and gives you a stable base. Check the current Umbraco release and support schedule when you plan, and allow time for packages to support the version you choose.

Common pitfalls to avoid

  • Underestimating custom backoffice code and package replacements.
  • Forgetting integrations such as forms, CRM, search and analytics.
  • Missing redirects for old URLs, which wastes years of search authority.
  • Not training editors on the new backoffice before launch.
  • Treating go-live as the end, with no monitoring or plan for the next upgrade.

Frequently Asked Questions

Is Umbraco 8 still supported?

No. Umbraco 7 and Umbraco 8 have both reached end of life and no longer receive security updates, so sites on them should plan an upgrade.

Can I upgrade directly from Umbraco 7 or 8 to the latest version?

Not with a simple in-place upgrade. Because modern Umbraco runs on a different .NET platform, code is moved or rebuilt and content is migrated. Within modern versions, upgrades are incremental.

How long does an Umbraco upgrade take?

It depends on the starting version, the amount of custom code and packages, and the volume of content. An audit gives a reliable estimate before work starts.

Will an Umbraco upgrade affect our search rankings?

Not if it is planned well. Keep URLs where possible, add 301 redirects for any that change, carry over page metadata and monitor Search Console after launch.

Should we choose an LTS or STS version of Umbraco?

For most business websites an LTS version is the better choice, because it is supported for longer and gives a stable base.
